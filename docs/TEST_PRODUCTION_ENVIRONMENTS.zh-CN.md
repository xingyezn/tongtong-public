# 测试环境与生产环境隔离及设备切换

## 环境隔离

测试后端不是单一环境：8081 是浩然的测试配置，8082 是浩鑫的测试配置。任何非 `main` 分支在构建或部署前，都必须由用户明确确认使用哪个端口，禁止根据分支名或历史默认值猜测。

| 项目 | 测试环境 | 生产环境 |
| --- | --- | --- |
| 后端端口 | 用户确认：`8081`（浩然）或 `8082`（浩鑫） | 按线上部署配置 |
| 运行配置 | `backend/config.test.yaml` | `backend/config.yaml` |
| 账号数据库 | `backend/data/test/tongtong-test.db` | 线上独立数据库 |
| OTA 入口 | 按确认端口填写 `http://<测试机IP>:<8081或8082>/ota` | 公网 HTTPS `/ota` |
| WebSocket | 由测试 OTA 接口下发 | 由生产 OTA 接口下发 |

测试进程禁止复用生产数据库。测试用户、设备绑定、对话、记忆和管理员
操作均只写入测试数据库。

## 启动测试后端

```powershell
$env:TONGTONG_ADMIN_PASSWORD = "替换为强密码"
.\scripts\start_test_backend.ps1 -PublicHost 192.168.31.237 -TestBackendPort 8082
```

启动后访问确认的端口（例如 `http://<测试机IP>:8082`），管理员登录后可从右上角进入
`/admin`。

共享服务器上的测试服务按用户确认使用 `8081` 或 `8082`，并使用对应的独立目录、服务单元和
SQLite 数据库；不要用测试配置或测试数据库启动线上服务。

## 管理与用量

- 管理员可禁用/启用用户或设备。禁用设备会断开当前连接，并拒绝后续连接。
- 设备管理可按所属用户筛选，并展示每个用户、每个设备的对话轮数及 Token 用量。
- 用户端展示今日、本周、本月和累计的对话轮数、输入 Token、输出 Token 和总 Token。
- Token 取自实时模型返回的用量数据；本功能上线前的对话无法准确回填 Token，历史
  记录会显示为 `0`。

## 发布到生产

1. 在功能分支完成本地测试后，先确认使用浩然 `8081` 还是浩鑫 `8082`，再部署到对应远端测试服务并验证。
2. 从最新 `main` 合并功能分支，解决冲突并再次运行测试。
3. 推送 `main` 后，才更新生产服务目录并重启生产服务。
4. 检查生产健康接口、管理员登录、设备连接和一轮真实对话；若异常，使用上一个
   Git 提交恢复代码并重启生产服务。

生产服务与测试服务不得共享数据库、运行配置或端口。

## 设备为什么只需要切换 OTA 地址

设备启动时先访问 OTA 入口。OTA 响应会下发当前环境的 WebSocket 地址，
设备随后连接该 WebSocket。因此环境入口的唯一真实来源是 OTA 地址；不要在
设备上分别维护一套 OTA 地址和一套 WebSocket 地址，否则容易出现跨环境连接。

固件读取顺序为：

1. NVS `wifi/ota_url`（运行时选择）；
2. 编译时 `CONFIG_OTA_URL`（没有 NVS 覆盖时的默认值）。

## 切换方法

### 已升级到支持环境切换的新固件

1. 在当前环境的管理员端找到在线设备。
2. 点击“切换环境”。
3. 选择 `test` 或 `production` 并填写目标 OTA 地址。
4. 后端向设备发送管理员系统命令；设备把地址写入 NVS 并重启。
5. 重启后设备从目标 OTA 入口取得目标 WebSocket 地址。

安全限制：生产地址必须使用 HTTPS；测试地址可以使用 HTTP 或 HTTPS。若测试端
通过公网暴露，应优先为它配置 HTTPS，避免设备 OTA 请求在公网明文传输。设备
必须在线，切换操作会写入管理员审计记录。

### 尚未包含环境切换功能的旧固件

旧固件无法接收远程切换命令。首次进入测试环境时，需要使用测试 OTA 地址构建
并刷写一次固件。升级到新固件后，后续即可从管理员端切换。恢复生产环境也可
刷回包含生产 `CONFIG_OTA_URL` 的固件。

## 注意事项

- 测试机与设备需要位于同一局域网，且防火墙允许设备访问用户确认的 TCP `8081` 或 `8082`。
- 从测试切回生产前，先确认生产 OTA 地址及 TLS 证书有效。
- 环境切换不会迁移账号、设备绑定、对话或记忆；两个环境的数据始终独立。
- 同一实体设备在两个环境中会分别生成登记记录，需要分别绑定测试账号与生产账号。
