# 端到端语音与 MCP 验证

本项目只保留真实麦克风的正常语音对话，不再提供虚拟麦克风、`test_audio` 或调试模式。

每项语音控制能力都应按完整链路验证：

`用户语音 -> ESP32 上行 Opus -> 后端 VAD -> Qwen-Omni -> 模型 function_call -> 设备 MCP -> JSON-RPC 回包 -> 模型语音回复`

它不同于 [MCP 手动硬件测试](MCP_BENCH_TESTING.md)：后者跳过模型，适合诊断 MCP 下半链路；本测试要求模型实际选择并调用工具。

## 正常语音验证

1. 通过唤醒词或触摸键开始正常对话。
2. 对设备说出真实用户指令，例如“把灯打开”。
3. 在后端日志确认顺序：设备 `listen:start`、服务端 VAD、模型推理、模型选择 MCP 工具、设备执行工具并返回 JSON-RPC 回包。
4. 对电机等物理动作，先让车轮悬空，并确认动作结束后处于停止状态。

## 下行音频完整性与回声回归

### 症状

- 模型文本或后端日志完整，但设备扬声器末尾字句没有播放，界面持续显示“说话中”。
- 或回复刚结束就恢复监听，把扬声器回声识别成新的用户输入，造成模型连续自言自语。

### 根因

后端曾在模型生成完成时突发发送所有 60 ms Opus 音频帧，而 ESP32 的下行解码队列只能容纳约 2.4 秒音频。音频生成快于扬声器播放时，后半段帧会使队列满；固件此前使用非阻塞入队，因而出现尾音被静默丢弃。长回复还可能在发送协程中被固定节奏等待，放大模型音频块间隔造成的播放队列见底。

此外，协议中的 `tts stop` 仅表示服务端下行流结束，并不代表设备已经播放完毕。若此时立即恢复麦克风监听，扬声器剩余声音会被 VAD 误判为新一轮语音。

### 解决方案

1. 后端先缓存 `1200 ms` 音频再启动播放；之后将已经生成的完整 60 ms Opus 帧立即通过 WebSocket 下发，不在模型音频接收协程中固定等待 60 ms。板端有限队列负责吸收突发数据。
2. 固件播放前预缓冲调整为 `20` 帧（约 `1200 ms`），播放队列上限为 `22` 帧，解码队列上限为 `40` 帧（约 `2.4 s`）。
3. 固件 WebSocket 音频回调在解码队列满时阻塞等待空位，而不是静默丢包；TCP/WebSocket 反压会使服务端发送自然暂停，保留长回复的后续音频。
4. 后端累计 PCM 总时长，在预计播放结束前不发送 `tts stop`，并保留少量传输余量；固件收到 `tts stop` 后继续等待本地队列和当前输出完成，再增加回声保护窗口。
5. 本板当前推荐的服务端 VAD 初始参数为：静音时长 `600 ms`、能量阈值 `600`。实际环境可在后端面板中继续校准。

### 本次调优记录（2026-09-12）

- 症状：长回复时字幕继续更新，但音频后半段无声。
- 直接原因：服务端快速突发下发使固件解码队列达到上限，原非阻塞入队丢弃了后续 Opus 包。
- 实施：服务端启动缓冲与固件播放前缓冲统一到 `1.2 s`；服务端取消逐帧 `sleep(60 ms)`；固件音频入队改为等待空位。
- 实测：长回复中解码队列达到 `40` 帧仍能完整播放，未出现丢包告警，字幕与语音均正常结束。
- 诊断日志：重点观察 `Audio queues: decode=... playback=...`、`Audio playback queue drained`、`Opus decode slow`、`Audio output slow`，并结合后端 `omni audio stream: ... max_gap=...` 判断是上游音频间隔还是板端队列问题。

### 回归检查

1. 通过唤醒词说“把灯打开”。
2. 后端日志应依次出现模型工具调用、`self.led.turn_on({})` 与设备成功回执。
3. 回复的尾字必须完整播放，设备随后才从“说话中”切回监听状态。
4. 回复结束后保持安静至少 10 秒，不应出现新的 `auto stop by server VAD` 或模型自言自语。

## 新功能测试标准

每个面向用户的新功能都应提供可重复的测试用例，并按同一链路验证：

1. 注册名称稳定的设备 MCP 工具，定义输入 schema、参数边界和确定性的 JSON 结果；记录命令与安全限制。
2. 先用 [MCP 手动硬件测试](MCP_BENCH_TESTING.md) 验证工具、设备执行与回包，再用真实语音验证模型是否能正确选择工具。
3. 核验后端日志中的监听开始、VAD 停止、模型轮次、模型工具调用、设备 JSON-RPC 回包与语音回复。
4. 验证非法或越界参数，以及安全停止或恢复路径；物理动作结束时必须处于停止/空闲状态。
5. 提交前运行后端回归测试与固件构建；私有端点、密钥和本地测试素材不得进入共享仓库，并在变更说明中记录测试命令与结果。
