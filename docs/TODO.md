# 后续待办

## 表情生成链路

- [ ] 研究可替代的表情生成方案，使表情能在语音开头同步显示，并由模型语义决定。
- 当前百炼 Qwen3.5-Omni-Realtime WebSocket 仅在**用户输入语音转写**事件中提供 `emotion`；没有独立的助手输出情绪事件。
- 不要继续采用“在助手要朗读的文本末尾追加 `{"emotion":"..."}`”作为长期方案：该 JSON 会进入音频转写，可能被朗读，且只会在回复末尾才可解析。
- 候选方向：探索接口原生结构化元数据、独立的低延迟文本/分类调用，或使用首句本地推断后由模型结果校正。

## 语音上行与首响延迟

- [ ] 缓存模型会话配置：在模型、音色、提示词、工具清单和 VAD 模式均未变化时，复用已建立的 Realtime WebSocket 会话配置，跳过每轮 `session.update` / `session.updated` 往返；配置变更时必须主动失效缓存并重新同步。
- [ ] 验证边说边上传模型的语音链路：改为将设备实时上行音频持续转发到 Qwen Realtime，并使用 `semantic_vad` 判定轮次结束，以降低“本地 VAD 结束后再整句提交”的首响等待。需单独验证与回声保护、打断、工具调用及断线恢复的兼容性后再替换现有稳定链路。

## 语音链路优先级优化

- [ ] 将固件音频上行发送从 `Application` 主任务中隔离，使用专用发送任务和有界队列，避免同步 WebSocket 发送阻塞语音状态机、VAD、唤醒和按键响应。
- [ ] 将摄像头拍照/识别、屏幕截屏/预览和 OTA 下载等耗时 MCP 操作从主任务中隔离，使用独立工作任务或异步状态机；主任务只处理轻量状态变化和结果回传。
- [ ] 为 MCP 工具调用增加独立的工作队列，避免单个耗时工具阻塞后续 MCP 调用、TTS 状态和字幕/表情更新，同时保证调用结果与请求 ID 一一对应。
- [ ] 处理 TTS 音频解码队列满的情况：当前网络回调可能静默丢包；增加丢包计数和受控告警，但不能为了等待队列而阻塞网络接收线程。
- [ ] 将重启工具及 OTA 环境切换中的固定 `vTaskDelay` 从主任务移出，改用定时器或独立任务，避免无意义地阻塞语音链路。
- [ ] 检查唤醒时同步打开音频通道的连接流程，必要时改为异步连接状态机，降低网络异常时的唤醒延迟。

## 专用 WakeNet 唤醒词

- [ ] 获取模型后，将模型目录（例如包含 `wn9_data`、`wn9_index` 和 `_MODEL_INFO_`）集成到 ESP-SR 资源构建流程，改用 WakeNet 唤醒词接口，关闭当前 `CONFIG_USE_CUSTOM_WAKE_WORD` + Multinet7 方案。
- [ ] 保留当前 Multinet7 版本作为回退方案；对新模型进行多说话人、距离、语速、噪声、播放中唤醒、误唤醒率和漏唤醒率测试，并对比 Flash、RAM、推理延迟和唤醒稳定性。

### HTTPS 切换前置条件

当前服务器尚未发现运行中的反向代理或可用 TLS 证书，因此暂不直接修改监听方式，避免设备和浏览器全部断连。正式切换前必须准备：

1. 指向服务器的正式域名。
2. 该域名的可信 TLS 证书及自动续期方式。
3. 反向代理配置，将 HTTPS/WSS 转发到本机后端端口。
4. 固件 OTA 地址、WebSocket 地址和管理后台地址全部切换并验证。
5. 验证完成后再关闭公网明文入口。
