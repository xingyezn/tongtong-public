# MCP 手动硬件测试

Dashboard 的“硬件手动测试”通过设备 MCP 通道直连调用已声明的硬件工具，用于验证电机、RGB 指示灯、摄像头、舵机/云台和屏幕等外设。

## 摄像头拍照与预览

点击“拍照测试”时，Dashboard 仍先通过 MCP 调用设备的
`self.camera.take_photo`。设备采集 JPEG 后，使用当前 WebSocket 会话在
`initialize` 阶段下发的一次性上传令牌，POST 到后端的
`/api/camera/upload`。后端只在内存中保留该设备最近一张照片；Dashboard
登录用户才能通过 `/api/camera/latest` 预览。照片不会写入磁盘、不会进入
Git，也会在后端重启或下一张照片到来时失效。

一次性令牌会在设备每次重连时更新，因此固件不保存面板口令或长期上传密钥。

当前童童固件会在启动、联网并完成激活后主动建立 WebSocket 控制会话，因此不必
先触摸或唤醒才能使用手动测试。此连接不会启动麦克风采集；但 Wi-Fi 需要保持活跃，
待机耗电会高于按需连接模式。

## 使用方式

1. 固件始终运行正常语音模式，不存在调试模式开关，也不会关闭麦克风或唤醒词。
2. 先用唤醒词或触摸键开始一次正常对话，让设备连接到后端。
3. 在 Dashboard 的“硬件手动测试”中选择在线设备并刷新测试项。
4. 点击测试按钮；结果区和后端 MCP 日志会显示设备回包。

测试电机前必须让车轮悬空，并使用低速度、短持续时间。未由设备声明的工具会显示为不可用，页面不会伪造测试结果。

后端只保留两个已认证接口：

- `GET /api/test/tools`：获取设备声明且允许手动测试的 MCP 工具。
- `POST /api/test/mcp`：调用一个允许手动测试的工具。

手动测试不会改变设备的语音模式。
