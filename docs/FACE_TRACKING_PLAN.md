# 摄像头人脸跟随开发计划

本文档只记录方案和进入开发前的检查项，设备未到齐前不实现功能代码。

## 目标

使用 USB 摄像头和两个 SG90 舵机组成 Pan/Tilt 二自由度云台，实现近距离人脸跟随。人脸检测和云台控制必须在设备本地实时闭环完成；云端大模型只负责响应语音指令，例如开始、停止和回中。

## 已知硬件

- 摄像头：M5-CSP 镜头模组
- 接口：USB 1.1/2.0，标称 5V，输出 YUV/MJPEG（实际格式需实测）
- 分辨率：优先验证 480×320；1280×720 暂不作为实时检测默认分辨率
- 视场角：约 65°
- 物距：约 5～20cm，第一版定位为近距离跟随
- 云台舵机：2× SG90
- 主控：ESP32-S3-DevKitC / WROOM，`N16R8`（16MB Flash + 8MB PSRAM），当前固件目标为 `bread-compact-wifi`

板卡资料说明 Type-C 原生 USB 支持 OTG，但要让 USB 口对外给摄像头供电，必须短接背面的 `USB-OTG` 跳线。CH343 USB 转串口接口与原生 USB 接口分开；摄像头应接原生 USB 口，烧录和串口调试使用 UART/CH343 口。

## 进入开发前的硬件检查

1. 确认背面 `USB-OTG` 跳线已短接；仅用锂电池给主板供电时，测量原生 USB VBUS 是否稳定为 5V。
2. 确认电池供电路径包含足够余量的 5V 升压，不能只依赖 USB 串口供电。
3. 确认当前 Type-C 接口支持 USB OTG Host，而不只是 USB Device/下载。
4. 插入摄像头后确认 USB 能枚举，并记录实际像素格式、分辨率和启动电流。
5. 确认 GPIO17、GPIO21 可作为 Pan/Tilt PWM 信号，未与板载外设冲突。
6. SG90 使用独立 5V 电源；摄像头和舵机不得直接由 ESP32 GPIO 供电。
7. 主板、摄像头和舵机电源共地；舵机启动和堵转时不得导致 ESP32 重启或 USB 掉线。
8. 确认摄像头、支架和上层舵机的总重量没有超出 Tilt 舵机的实际扭矩能力。

## 软件实施阶段

### 阶段一：摄像头 PoC

- 接入现有 UVC/`Esp32Camera` 框架。
- 增加持续取帧能力和帧缓冲管理。
- 以 480×320 或更低分辨率运行。
- 连续运行 5～10 分钟，记录帧率、内存和掉线情况。

### 阶段二：人脸检测 PoC

- 引入并锁定 ESP-DL 版本和轻量人脸检测模型。
- 先只输出人脸框、中心点、置信度和推理耗时。
- 无人脸时不驱动舵机，多人脸时采用明确的首选策略。

### 阶段三：SG90 云台驱动

- 使用 LEDC 输出两路 50Hz PWM。
- 初始角度 90°，软件限制在安全角度范围内。
- 增加平滑插值、最大单步变化量、回中和停止输出。
- 先手动控制舵机，不接人脸检测。

### 阶段四：本地 PID 跟随

- 根据人脸中心与画面中心的误差控制 Pan/Tilt。
- 增加死区，避免舵机抖动。
- 连续检测若干帧后进入 TRACKING。
- 丢脸超过约 1 秒时回中并回到 IDLE。

### 阶段五：MCP 与语音控制

增加以下工具：

- `self.face_tracker.start`
- `self.face_tracker.stop`
- `self.face_tracker.center`
- `self.face_tracker.get_state`

语音端到端测试使用现有流程：

```text
模拟语音 → 设备音频上行 → 后端 VAD → 大模型 → MCP → 设备回执
```

实时人脸检测和 PID 必须另行进行本地实时测试，不能只用语音测试代替。

## 测试与完成标准

- 摄像头能够稳定枚举并持续取帧。
- 人脸检测在目标距离内稳定工作。
- Pan/Tilt 能跟随缓慢移动的人脸，不明显抖动或撞限位。
- 无人脸、掉线、Wi-Fi 重连和舵机停止均进入安全状态。
- 摄像头和舵机同时工作时，音频、Wi-Fi 和主控不重启。
- `start/stop/center/get_state` 均完成 MCP 回执测试和语音 E2E 测试。
- 完成至少一次长时间稳定性测试后，才允许合并功能分支。

## 分支流程

电机功能合并到 `main` 后，从最新主分支创建：

```bash
git switch main
git pull --ff-only origin main
git switch -c feat/face-tracking
```

每个软件阶段独立提交并验证；设备未到齐前只维护本文档，不创建实现代码或模拟硬件结论。

## 模型方案确认（人脸跟随第一版）

第一版只做人脸检测和云台跟随，不做用户身份识别。采用 Espressif ESP-DL 的 Human Face Detection 模型，优先选择适配 ESP32-S3 的轻量模型。

### 纯软件跟踪控制器

云台控制已先抽象为 `FaceTrackingController`，与 GPIO/PWM 舵机驱动解耦。每次检测输入人脸框和图像尺寸，控制器计算归一化中心误差，并执行以下策略：

- 水平/垂直比例控制（Pan/Tilt 独立 Kp）；
- 5% 画面中心死区，减少舵机抖动；
- 每帧最大角度变化 6°，限制突变；
- 舵机角度范围限制：Pan 20–160°、Tilt 45–135°；
- 丢脸 1 秒内保持，超过后以 2°/次缓慢回中；
- 输出仅为目标角度和锁定状态，后续 SG90 驱动层负责转换为 PWM。

该控制器可在无摄像头、无舵机时单独进行单元测试；接入真实设备后建议以 5 FPS 调用，并根据云台机械方向校准 Pan/Tilt 正负号和 Kp。

- 检测输出：人脸边界框、中心点、置信度（可选关键点）。
- 控制输入：以人脸框中心与画面中心的偏差驱动 Pan/Tilt PID。
- 图像参数：先验证 480×320，检测帧率目标 5–10 FPS；实际以测试为准。
- 存储分配：模型权重放 Flash，图像缓冲区和推理张量优先放 PSRAM。
- 多人策略：默认跟随最大（近距离）人脸；无人脸时停止驱动并回中。

后续如需“只跟随指定用户”，再在检测模型基础上增加 MFN_S8_V1 等特征识别模型，不纳入当前版本。
